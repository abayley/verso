Architecture review — the editor frontend

src/Verso/Editor/ (60 modules, ~14,100 lines) plus static/editor/markdown-editor.css (hand-written source, 123 commits in 3 months — the hottest file in the codebase) · 2026-08-05 · main @ c51cc67

module seam leakage deep module
The coverage gap tracks the seams exactly: every module with an injected port has a test; every module that reaches for document/window/fetch directly has none. 33 of 59 modules have no test file, and the one door into the real content pipeline is a 2,279-line test file that boots the whole editor shell per assertion. Most candidates below are that observation, cashed out.

2 · A protected-fragment pass on the pipeline that ships

Strong in-process

tiptap-visual-editor.ts (:166–189, :465–529, :546–1185)

Before — five hand-rolled strip/load pairs, order in comments

stripFencedCode → sentinel \u{E000}
extractFootnoteDefinitions → \u{E001}
extractReferenceDefinitions → \u{E002}
extractRawHtml → \u{E003}
extractBadges → \u{E004}
…then an 11-step load sequence, written out twice (constructor :465–478 and setMarkdown :516–528), same ordering comment pasted into both.

After — one pass, features contribute one value

protected-fragment pass

owns: sentinel allocation · strip order · restore order

fence {find, restore}
footnote {find, restore}
reference {find, restore}
raw-html {find, restore}
badge {find, restore}
next feature…

Load sequence encoded once; order is a structure, not a comment.

Problem — per ADR-051 the remark path is test-only, so the pipeline production actually runs (marked → ProseMirror DOM) has no extension seam at all: ~470 lines of the visual view are a compatibility layer over marked's gaps, five constructs each get an independently-written sentinel strip/load pair, and every content feature is implemented twice — with only the dead copy unit-tested.

Solution — one interface for the sentinel round-trip: an ordered list of {find, restore} pairs owned by a single pass; each feature contributes one pair.

  • locality: one place owns strip/restore order
  • five hand-written pairs become five values
  • two duplicated 11-step sequences become one
  • with c1: round-trip testable as one function
Respects ADR-051 (round-trip stability by offline trust) and ADR-041 — this doesn't reinstate the validation gate, it names the seam ADR-041's registry promised but only delivered on the test-only path. Mermaid (ADR-071) is the proof the target shape works: one feature, three files, no registry entry.

7 · A liveness gate for chrome class names

Strong in-process

markdown-editor.css · the 20 files producing markdown-editor__* names · Makefile (chrome-gates)

Before — renames drift silently, in both directions

CSS :600 .markdown-editor__nav-trash → produced by nothing
CSS :608 __nav-trash-heading → dead
CSS :612 __nav-trash-row → dead
CSS :1191 __theme-option → dead
CSS :1195 __button-icon → dead

The other direction is worse: a themed rule that stops matching is a visual regression only that theme's users see. The Moebius block names 40 chrome classes; tests pin ~30 more.

After

build-time liveness check

every markdown-editor__* selector in the CSS
must be produced somewhere in src/

One grep in the existing chrome-gates target. Would have caught all five dead rules. Converts an invisible hazard into a failing build.

Problem — no test, type, or build step ties a TS-produced class name to a CSS selector; a chrome rename is a 3–4 place edit (producer, base CSS, theme block, tests) and the base chrome has already leaked five dead selectors — the exact hazard ADR-081 accepted with greppability as the only control.

Solution — a chrome-gates check asserting every markdown-editor__* selector in the CSS is produced in src/; optionally grow it into a declared themable-regions vocabulary later.

  • cheapest candidate on this list
  • already caught five real dead rules
  • protects every future theme, not just Moebius
ADR-081 knowingly accepted the rename cost with contiguity + greppability as the mitigation. This doesn't contradict the ADR — it adds the control the evidence shows was missing.

Solution — the registry becomes an explicitly constructed value (extension list + mode); the custom payload becomes a registry-keyed typed map; the callout family becomes one module two features configure. Delete the pass-through shells and the third grammar.

  • silent-omission hazard closed
  • seven guard-and-cast preambles deleted
  • naming stops misleading about the pipeline

Top recommendation

1 · One editing-surface interface

Two agents converged on this seam from opposite directions, it owns the sharpest friction found (three unnamed, incompatible definitions of “which surface is live”), and its first concrete step — constructing TiptapVisualEditor without the host — is also the seam candidate 2 needs to put round-trip stability tests on the pipeline that ships.
